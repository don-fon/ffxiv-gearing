# 独立精确最优性证明

> 当前决定（2026-10-30）：HiGHS 已退出当前求解、验证和基准流程，仅作为[未来可选项](optimizer-highs-future-option.md)归档。下文接入状态、命令与测量属于历史研究记录。

2026-10-30。实验整数求解流程增加独立证明生成与核验，不按职业、GCD或减伤条件启用不同算法。网页默认求解器未切换，未部署。

## 能保证什么

在下述输入语义及可信内核正确的前提下，**检查器接受完整证书，则返回配装是该输入原始候选域中的全局最优；接受无解证书，则该域内不存在满足用户条件的方案**。时间／节点预算耗尽、输入尚不支持、证书损坏或核验失败时，一律为`unproven`，不能称为最优。

这不是把HiGHS的`Optimal`再检查一遍，也不是由有限测试推出全输入正确。HiGHS只提供候选，证书从原始装备、魔晶石和食物覆盖全部可行选择。证明不依赖MILP是否漏候选、浮点对数误差界是否准确或HiGHS是否错误判定最优。

可信基础是约400行的独立内核、标准整数／有理数运算及输入参数。内核本身还没有经过Lean、Coq等工具的代码级形式化验证；这里给出的是精确证书检查规则及数学正确性论证，不声称整个软件栈已经形式化验证。

## 输入问题的精确定义

范围是提交给实验入口的**原始完整输入**，不是HiGHS内部已经筛选或分片后的候选。候选范围本身是否符合UI装等筛选，仍由输入构造负责；证书不会凭空证明外部装备数据库的真实性。

- 选择输入要求的部位，戒指选择两件；遵守唯一性、锁定、排除与食物范围。
- 同步装备没有有效魔晶石。未锁定装备每个可用孔选择输入允许的一种最高值魔晶石；明确锁定的镶嵌按声明保留，可为空。这与现有自动求解域一致，不是证明任意未声明的低等级／空孔扩展问题。
- 使用整数属性、整数向下取整和十进制参数的有理数值计算GCD、减伤、伤害和折算目标，不使用浮点容差。支持域要求属性不低于相应基础值、相关取整中间式非负、倍率为正；不满足时拒绝认证。
- 高／低暴击范围从这个原始域的可行方案精确推导，跨全部食物共享；不会信任输入预填的`criticalRange`。
- `globalMinimumDamage`、`targetSpeedContribution`等搜索提示不属于最终用户约束，证明时不允许它们缩小原始问题。只有经过核验、实际可达到的候选才提供证明剪枝界。
- JSON中cap的`null`和缺省值表示无该属性上限，与求解器的空值处理一致。显式锁定的等级／数值必须能由输入孔位核实，否则不认证。

## 三层实现

1. `optimizer-integer-certified.mjs`仍负责浮点整数规划候选搜索，直接返回值明确标记`solver-claim-only`。
2. `optimizer-proof-producer.py`生成排除树及可达到的答案见证。它不受信任；搜索策略、排序或剪枝出错，不能自动获得认证。
3. 独立进程`optimizer-proof-checker.py`不导入证明搜索器，从同一原始输入重新构造域、重算每个证明节点。最终只使用它重构的结果。共同使用的`optimizer-proof-kernel.py`是可信算术与推理规则。

`optimizer-strict-proof.mjs`串联两个独立进程。`benchmark-optimizer.mjs --integer-model --integer-recovery`统一执行完整流程，没有跳过证明的案例选择。条件路由／限时切换参数现明确拒绝使用。

## 完备性：只做精确等价归并

单件装备的魔晶石赋值直接从原始孔位逐项展开，不调用原生支配筛选。相同ID、完全相同全部属性的不同镶嵌只保留一个合法见证：所有后续条件和目标对这些见证都相同。

跨ID归并也只针对严格对称的ID：在完全相同的部位域中，它们必须具有完全相同的**完整属性菜单**，且唯一性标志相同。要求锁定的ID不参加归并。

若一类非唯一ID满足条件，保留一个代表；若一类唯一ID出现在m个选择域中，至少保留`min(m, 类大小)`个不同代表。任意可行配装至多从这类中选择m个不同ID，可将其注入映射到保留代表，并为每件保持相同属性与合法镶嵌。因此得分、GCD、锁定及唯一性保持，最优值不变。检查器从原始菜单自行重建这些类，不相信生产器声明的等价关系。

这不使用“暴击更高所以支配”等依赖目标的筛选。属性存在与数值0也区分处理，尤其TEN缺省值不能误当作显式0。

## 精确上界为何安全

对一个部分选择，逐组汇总剩余属性的最小值和最大值，得到所有后继方案的外包范围。百分比食物及取整是单调的，因此可以得到安全的最终属性范围。

支持域内，主属性、武器、暴击、信念、直击、坚韧的伤害因子均非负，且分别对相关属性单调。把每个因子替换为其范围中的上界，乘积仍不小于任何真实后继分数。不同属性上界不能同时达到只会使上界更松，不会导致漏解。

蓝魔武器增伤表不假设单调：独立取可能INT索引区间中的表项最大值，并覆盖越界时的0，再与主属性等上界组合。坚韧折算同样使用非负、单调的减伤上界。低暴击上限仅可将最终CRT上界裁到精确阈值，高暴击下限反向处理。

GCD与速度单调对应，减伤上限、无法再补齐的锁定ID和已违反的唯一性也提供可重算的不可行理由。所有运算使用`Fraction`／整数，未使用epsilon、近似对数或浮点dual bound。

## 证书规则与正确性论证

证书绑定原始输入，并声明选择域的完整排列。对每个食物都有一棵根树，节点仅允许：

- `S`：分支，必须恰好覆盖下一个选择域的全部规范化选项，少一个、多一个都拒绝。
- `I`：不可行，检查器必须用自己的区间、唯一性或锁定条件重算并确认。
- `B`：界限，最大化时检查器重算上界，必须不超过最终见证的真实分数；最小CRT阶段反向比较下界。
- `L`：完整叶子，必须已经选择所有域。检查器重算约束和真实有理数分数，不能存在击败声明答案的可行叶子。

首先核验声明答案是一个真实可达到的见证，而不是任意数字上界。然后对树作归纳：每种合法后继要么被某个分支覆盖，要么有有效不可行理由，要么其目标被安全界限压住，要么到达已直接核算的完整叶子。树完整通过，则没有更优后继；加上可达到见证，得到最优性。没有见证时，界限节点不能使用“虚构答案”，所有后继必须被证明不可行，才能返回无解。

高／低暴击需要先分别证明全局最小与最大CRT，再精确计算1/4或3/4阈值，最后证明伤害目标。漏掉端点阶段、食物、任意分支或最后的伤害阶段都拒绝。

检查器使用最终见证核验所有节点。生产器中途更新候选不会破坏证明：最大化的最终候选不低于早期候选，所以此前能排除的上界仍可排除；最小化同理。

## 状态与成本

- `certified-optimal`：完整证书通过，结果由检查器重建。
- `certified-infeasible`：原始问题的无解证书通过。
- `unproven`：没有完整有效证明。保留候选，退出码2；不能把候选当作最优结果。

严格实验入口只有认证成功才保留`result`并报告`completed`，失败／超时时仅保留`candidate`。`searchStatus`与`searchMilliseconds`记录原候选搜索，`optimality`单独记录证明生成、核验、证书路径；总`milliseconds`包含新增证明成本。

生成与核验都可能很慢，最坏情况需要大规模精确搜索；没有运行时间保证。默认分别给生成和核验30秒预算。生成未完成的证书会被检查器立即拒绝，不伪装为快速认证。此版本用于验证严格保证与测量代价，尚未证明能在实际慢例上同时满足性能采用门槛。

## 复现

```sh
node scripts/benchmark-optimizer.mjs --input test/fixtures/pictomancer-375-phantom-input.json \
  --integer-model --integer-recovery --workers 4 --proof-timeout 30000 \
  --output /tmp/pct-strict.json
python scripts/experiments/optimizer-proof-checker.py \
  --input /tmp/pct-strict.json.run0.input.json \
  --proof /tmp/pct-strict.json.run0.certificate.json \
  --output /tmp/pct-independent-check.json
python scripts/experiments/test-optimizer-proof.py
```

证明文件必须交给检查器核验；生产器自己写出的`complete:true`不构成认证。没有`--output`时证书保存在返回的临时目录路径中。需要更长预算可调整`--proof-timeout`，但不能因此假定一定会证完。

## 本轮验证与实测

512个独立原始组合枚举问题的证书均被接受，结论与有理数枚举最优值一致；共重放29932个证明节点。10种证书结构篡改被拒绝，另有可达到但次优的伪造界、输入绑定、零预算、未完成证书、旧报告文件、非单调蓝魔表、唯一戒指等价归并、锁定、null上限、伪造候选分数及聚合属性溢出的针对性检查。

最终实验入口也确认：认证通过时才有`result`，预算不足时只有`candidate`、状态`unproven`且退出码2；输入／证书字节哈希与规范输入哈希均绑定至独立检查报告。

| 输入 | 候选搜索秒 | 新增证明阶段秒 | 已用总时间秒 | 结果 |
| --- | ---: | ---: | ---: | --- |
| 小型协议测试 | 0.157 | 0.088 | 0.245 | 已证明最优 |
| 画家375／2.50完整候选池 | 9.255 | 30.129 | 39.383 | 证明生成预算耗尽，仍未证明最优 |
| 战士375／2.50完整候选池 | 40.707 | 30.096 | 70.803 | 证明生成预算耗尽，仍未证明最优 |

两个完整案例统一给证明生成30秒预算，均未证完。总时间是已经付出的搜索与证明时间，不是最终完成时间；尚不能估算真正证完需要多久。此版本补上了不误报最优的独立证明机制，但没有达到“大例仍快速完成”的实际采用要求，不切换网页、不部署。

完整耗时对应cap-null修复后的冻结版本。随后只加固了协调器的报告绑定和聚合整数范围检查；最终小型协议测试单独重跑，没有把早期未进入证明搜索的兼容错误时间当作证明成本，也没有把未重跑的完整例称为最终版本精确性能对照。
