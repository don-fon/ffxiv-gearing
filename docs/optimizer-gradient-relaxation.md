# 连续松弛辅助精确搜索实验（2026-10-27）

本轮测试的是“梯度方法辅助精确搜索”，不把连续解直接作为配装结果。
生产求解器暂不采用本实验。实验补丁独立保存在
[`experiments/gradient-relaxation.patch`](experiments/gradient-relaxation.patch)。

## 实验方法

基线为 `29a044a` 的原生 WASM 求解器。它已有逐 CRT 区间的对数切线上界，
并不是简单枚举。本实验调整切线参考点，以及 CRT / 原始技速约束的线性乘子：

1. 每个候选组放松为候选属性向量的凸包，用 Frank–Wolfe 条件梯度步骤更新属性参考点。
2. 在每个 CRT 区间最多迭代 16 次。平滑目标使用区间内 CRT 因子的割线上界，
   其他伤害因子的对数；食物保留连续的封顶规则。
3. 对 CRT 区间和技速区间的偏离加二次惩罚，以 12 次方向导数二分选步长。
   这些惩罚只用于寻找参考点，不改变实际配装目标和可行域。
4. 由参考点生成切线，并加上对可行解非负的线性约束项。仅这些安全的线性上界用于剪枝，
   不把局部梯度收敛、惩罚函数值或不可行的连续解当作全局最优证明。
5. 在根节点选择测得最紧的切线，包含原来的切线作为候选。
6. 初始解分支检查每轮线性子问题返回的整数候选组合；只有精确 GCD、暴击和坚韧条件都成立时，
   才按游戏的原始取整公式更新当前最佳解。本轮未实现额外的整数修复器。
7. 最终仍穷尽原分支定界搜索的全部必要分支。坚韧折算保留现有乐观减伤乘数上界。

三种变体使用同一迭代过程：`RELAX_MODE=1` 仅使用合法初始解、`2` 仅使用上界、`3` 两者同时使用。
仅初始解变体仍承担生成梯度候选的成本，最后恢复原来的剪枝上界。

## 测试口径

真实 Chromium、生产 Worker 流程、4 Workers、`--engine auto`，每次新浏览器冷启动。
计时包含规划、候选处理、WASM 初始化和全部分片返回，不传已知最优解。
场景及变体顺序执行，不同时运行多个基准。每次超时上限 300 秒。
每个单元格为一次完整运行，不能把很小的差异解释成稳定收益。
基线不限暴击运行期间曾有约数秒的编译和算法测试，不能把这部分波动算成算法收益；
同时记录分支数，区分搜索量变化与运行环境波动。

- 武僧：同步 605、350–795、幻武暴击/信念满、直击 108、GCD 1.94；不限／高／低暴击分别测试。
- 战士：同步 375、350–375、GCD 2.50，默认目标和每 0.5 个百分点减伤折算 1% 伤害分别测试。
- 画家：同步 375、350–795、幻武暴击/信念满、直击 108、GCD 2.50。

完整数值见 [`benchmarks/gradient-relaxation.json`](benchmarks/gradient-relaxation.json)。

| 场景 | 原版（秒） | 仅初始解（秒） | 仅上界（秒） | 两者结合（秒） |
|---|---:|---:|---:|---:|
| 武僧不限暴击 | 162.22 | 159.79 | 44.60 | 48.64 |
| 武僧高暴击 | 43.19 | 44.89 | 47.26 | 48.48 |
| 武僧低暴击 | 33.54 | 49.91 | 43.71 | 47.25 |
| 战士默认 | 6.78 | 8.04 | 8.40 | 8.08 |
| 画家默认 | 2.06 | 2.12 | 2.36 | 2.06 |
| 战士坚韧折算 | 7.67 | 10.23 | 11.87 | 12.49 |

## 结论与原因

本轮原型不通过采用门槛。武僧不限暴击有超过 50% 的完整耗时收益，
但高暴击、低暴击和战士出现退步，不能据此作为通用优化启用。

- 仅上界与组合方案在六个场景中的搜索分支数一致：当前整数顶点初始解策略未带来额外剪枝收益。
  很小的耗时差异不应算成初始解优化效果。
- 不限暴击武僧的分支数从约 5.77 亿降到约 9510 万，上界改善有实质作用。
- 高暴击的分支数反而由约 9572 万增加至 1.14 亿。根节点上界更紧，
  不代表同一切线在每个子树上都更紧；替换原来的切线也会影响搜索路径。
- 低暴击的分支数从约 199 万降到约 76 万，但原版内核搜索只占较小部分，
  每个区间反复扫描候选和梯度迭代的成本超过了省下的搜索。
- 画家的搜索分支数没有改变；秒级测试中的细小差异没有稳定收益证据。

后续值得验证的是按收益决定是否迭代，以及同时保留原上界与新上界、逐子树取较小值，
而不是硬编码某个职业启用。它们尚未在本轮实现，不能计入本轮性能收益。
本结论只否定当前原型的通用采用，不是否定所有连续松弛方法。

## 正确性和局限

三种实验变体均运行完整 77 项算法测试；原有的 300 组独立穷举对照扩展为 900 组，
候选组数从固定 3 组扩展为 3–5 组。包括食物封顶、分数属性、GCD、暴击限制和坚韧折算。
实测场景逐项比较最终目标值；坚韧折算比较 score，其他情况比较实际 damage。

这些测试支持当前原型在被测范围内正确，不能证明所有自定义极端数据都安全。
该补丁是实验材料，未作为生产内核启用，也未发布到 preview 或正式页。

## 复现

在独立工作目录中使用上述基线及当前测试文件：

```sh
git apply docs/experiments/gradient-relaxation.patch
# 默认 RELAX_MODE=3；分别改为 1 / 2 做消融对照。
npm run build:optimizer-wasm
npm run test:optimizer
npm run build
node scripts/benchmark-optimizer.mjs --skip-build --chromium /usr/bin/chromium \
  --engine auto --workers 4 --critical none --timeout 300000 \
  --input test/fixtures/monk-605-phantom-input.json --output /tmp/gradient-mnk-none.json
```

原生构建需仓库固定的 LLVM 19 工具链，可通过 `WASM_CC` / `WASM_LD` 指定。
高／低暴击分别改 `--critical high/low`；战士输入使用
`test/fixtures/warrior-displayed-375-input.json`，画家使用
`test/fixtures/pictomancer-375-phantom-input.json`。
战士折算输入从同一战士输入复制，仅将 objective 改为
`{"type":"tenacityTradeoff","mitigationPointsPerDamagePercent":0.5}`。
