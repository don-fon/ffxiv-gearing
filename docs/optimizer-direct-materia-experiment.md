# 将装备选择与魔晶石分配拆开求解

状态：本实现已因真实浏览器错误Optimal被否决，不能采用或部署。戒指对称表达调整后，Node回归通过，但浏览器武僧1.93仍返回较差结果；未修复。反例与当前原生消融见[重新验证](optimizer-algorithm-retest.md)。

以下为原实验历史记录。部分案例当时与参考最优值相同、耗时较短，但不能据此宣称模型普遍正确，或继续以这些耗时决定采用、组件去留。实验尚未接入网站。

哪些组件对哪些案例仍关键、哪些只剩历史证据，集中记录在[算法—案例证据台账](optimizer-case-dependencies.md)。本实验的整体收益不证明其复用的每项旧优化都必需。

## 历史完整任务结果（不作为采用证据）

冷启动 Chromium、4 Workers；计时包含原有候选规划、模型加载与构建，以及全部食物分片的精确求解。各次性能运行依次进行，没有并行运行其他基准、构建或测试。

| 输入，不限暴击 | 原有求解器 | 装备与魔晶石分开建模 |
| --- | --- | --- |
| 骑士605，580–605，GCD2.45，最低减伤10% | 超过300秒 | 65.426秒；仓库内实验入口复跑68.101秒 |
| 战士375，350–375，GCD2.48，最低减伤15% | 超过300秒 | 31.895秒 |
| 骑士605，GCD2.45，最低减伤15% | 42.696秒 | 41.500秒 |
| 战士375，GCD2.48，最低减伤10% | 88.286秒 | 23.078秒 |
| 画家375，幻武，GCD2.50 | 本轮复测2.802秒 | 6.541秒 |

这些历史运行相对于原先300秒的超时下限，记录耗时分别少77.3%、89.4%；同一实现的浏览器反例现已使采用结论失效。最优伤害分别仍为 `21.165158132308274`、`7.859572391399585`，每个分片都完成最优性求解或不可行证明。独立重建了最终装备、魔晶石、食物属性，并核对槽位、唯一装备、GCD和最低减伤。两个较快的坦克对照及画家也都得到原先的最优值。

画家这例体现了新求解器的启动开销。长任务明显变快，并不意味着所有短任务都更快；这些结果不足以直接全局替换发布页的求解器。

## 改变的是什么

之前的整数模型把“某件装备及其某种完整镶嵌方案”作为一个选择变量。同一件装备的基础属性、孔数和上限，会散落在许多完整方案中。

新模型分别表达：

- 每个槽位选择哪件装备，用0/1变量表示。
- 这件装备每种等级的魔晶石分别分给哪些属性，用整数数量表示；同等级孔共享数量约束。
- 属性的实际增加严格等于 `min(投入的魔晶石属性, 装备剩余属性上限)`，通过溢出选择变量精确表达。
- 两只戒指、唯一装备、已锁定魔晶石、食物上限、速度及坚韧条件仍有明确约束。

求解器能直接调整“这个等级的魔晶石从信念挪一个给坚韧”，并共享同一装备的约束。骑士圆蛤羹分片包含伤害查询表的总变量数由2868降至1497。

伤害仍使用原来的逐档公式和精确查询表；正因子的乘积取对数后求和，保留之前验证过的参考值归一化、目标缩放及严格容差。HiGHS内部仍会使用上界；本轮验证的是改变决策结构的收益，而不是把额外上界计算塞进原搜索循环。

实验的候选适配器仍复用现有候选生成，以取得候选ID、锁定规则及属性范围；因此目前并未消除前处理阶段的全部镶嵌展开。

## 当时的局部消融（需通过正确性后重新确认）

骑士在启用候选共享和分片重启时，两次完整耗时为99.720秒、100.218秒。关闭这些重启后为65.426秒、68.101秒。这个输入上，重启造成了额外工作，因此实验入口默认禁用重启，不将其作为新模型的必要组成部分。

也测试了技速与最低坚韧的动态规划预过滤。对食物49248，骑士两个减伤要求下，1966个候选均保留；战士从2573降至1972。该离线计数没有证明端到端加速，未并入新求解器。

另一项“先用LP安全收紧属性范围，再完整求解”的骑士实验仍在300秒时仅完成5/6，也未采用。

## 测试边界与诊断复现

仓库内测试将新模型与原精确JS求解器比较900个小规模输入，覆盖战士、龙骑、白魔、青魔，高/低/不限暴击，坚韧要求、减伤换伤害、不同武器属性、食物、固定速度贡献、锁定装备、双戒指、混合等级魔晶石及属性溢出。包括185次添加全局目标门槛的对照；最优值或不可行判断均一致。测试同时从提交的装备及魔晶石独立重建属性。本轮真实浏览器反例说明，小规模及Node测试通过仍不足以证明这个实现正确。下列命令仅作诊断，不能视为采用验收。

```sh
npm run test:optimizer-integer -- --count 900
npm run benchmark:optimizer -- --integer-model --engine auto --workers 4 \
  --chromium /usr/bin/chromium --timeout 300000 \
  --input test/fixtures/paladin-605-minimum-10-gcd-245.json
```

战士输入为 `test/fixtures/warrior-375-minimum-15-gcd-248.json`。需要已有构建时可加 `--skip-build --dist <目录>`；实验入口默认 `--restart-limit 0`。

核心模型见 [optimizer-integer-model.mjs](../scripts/experiments/optimizer-integer-model.mjs)，求解器固定为开发依赖 `highs@1.15.4`。只在传入 `--integer-model` 时替换基准里的求解Worker，原生产Planner继续参与计时；网站构建不包含该实验依赖。

完整结果、配装、分片统计、输入哈希及校验记录见 [direct-materia-results.json](experiments/direct-materia-results.json)。
