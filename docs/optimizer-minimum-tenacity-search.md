# 最低坚韧减伤搜索优化（2026-10-28）

停止逐子树梯度/张量重算，改进普通精确搜索的候选索引和分裂顺序。保持原目标GCD、最低减伤、高低暴击和候选范围，
没有新增职业或减伤数值特例。最优性仍由原来的完整分支定界搜索证明。未部署。

## 实现及适用原因

原候选树主要按属性不同取值的数量划分。同一节点混合高低TEN方案时，各副属性独立最大值可能来自不同候选，
虽然上界安全，但不容易排除实际上无法兼得的属性组合。这里是索引与约束不匹配，不能只凭装备件数解释实际访问量。

- **约束索引**：保留武器伤害、主属性优先；有正的最低减伤要求时，完整搜索后续先按TEN划树，收紧每个节点内的TEN范围。
  所有候选保留；没有最低减伤时沿用原索引。WASM完整搜索和JS状态/末尾候选树共用这一规则。
- **约束压力排序**：保留原主属性不确定性优先级；同优先级下，比较每组TEN/CRT/技速的跨度相对当前约束余量的影响，
  优先分裂影响最大的组。没有压力时回到原候选数排序。规则按输入约束工作，不按职业分流。
- **保留有限预热的原顺序**：预热有步数上限，目标是先找到强的可行解；完整搜索负责证明最优。
  把适合证明阶段的新顺序也用到预热，会改变有限预算内找到的解，反过来削弱后续所有分片的剪枝门槛。
  因此预热保留原索引和排序，新索引与新排序用于完整搜索。这是按任务职责区分，不是按测试案例开关。

WASM节点从25个f64增加到26个，只新增原始TEN最小值；ABI11同步更新适配器和内核。
`start_search`增加完整搜索标志，由是否存在`branchLimit`决定。没有增加局部梯度、张量、切线或传播缓存。
ABI8–10已用于实验；不同ABI的二进制和适配器不能单独混用。

另外独立修复原武器排序只读PDMG的问题：法系使用MDMG，物理使用PDMG。
物理/法系同构回归要求伤害、完整组合数和分支数相同；正式配对基线已包含修复，避免混算收益。

## 为什么先前20%会反而变慢

最初把两项策略同时用于预热和完整搜索：10%约5秒，但20%从73.84秒退化到177.07秒。
拆开后，只有新排序的版本仍需182.48秒；只有新索引的版本300秒超时，不能认证最优。
因此没有直接采用最初组合，也没有增加“20%禁用”这样的阈值例外。

12秒诊断采样发现：20%旧预热已找到最终最优值7.815015753261338；新排序预热只有7.814995333498104，
相差约0.00026%。主慢分片（食物49240）的参考属性相同，但启动剪枝门槛不同；当前并行任务不会在运行中接收其他分片更新的全局最优值。
这样小的可行解差异也可能允许大量离散属性分支继续通过，不能用接近最优的伤害比例估计证明最优所需时间。

保持完整搜索的新排序不变、仅恢复原预热，20%降到9.88秒；再保留只用于完整搜索的TEN索引，降到6.00秒。
这个对照证明预热变化是原退化的重要来源，不能把182→9.88秒全部归为排序公式的数学改进。
该差异也包括预热所得参考属性的变化；目前没有逐子树追踪所有上界差异，故不作更强的单因归因。

## 最终实现逐项验证

以下均为4 Workers、真实Chromium、完整流水线；普通基线包含物理/法系对称性修复。
单项表每格一次，时间差不提供统计置信区间；三轮正式配对见下节。

| 实现 | 最低10%秒 | 最低20%秒 |
|---|---:|---:|
| 普通版本 | 17.27 | 76.12 |
| 只改完整搜索索引 | 8.95 | 24.47 |
| 只改完整搜索排序 | 7.38 | 9.88 |
| 两项组合，保持原预热 | 5.51 | 6.00 |

每项都做单独构建与原生测试，也比较了在另一项之上的边际价值。组合满足至少50%完整耗时下降的要求。
早期14项消融还测过固定TEN资源价格上界、节点属性下界、TEN及全约束传播。资源价格上界单独只从16.96降到15.60秒，
节点下界17.99秒，约束传播11.61秒；在早期索引+排序上再加价格上界只省约0.28秒。
这些额外逻辑没有足够的独立或边际收益，不进入最终实现。早期消融包含对预热的修改，不能直接当作最终生产改动的单项数字。

尚不能保证未测输入必然加速，也没有用这些有限样本推算用户总体平均收益。
