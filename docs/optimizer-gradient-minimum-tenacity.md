# 最低减伤10%的梯度回退归因（2026-10-28）

场景为统一后的战士375、GCD2.50、最低坚韧减伤10%，4 Workers。
最优解TEN814，减伤恰好10%，说明该约束在最优解处是活跃的。

## 已确认的实现缺口

原梯度细化只对CRT区间和技速区间加入惩罚/线性乘子；最低TEN下界没有进入梯度方向或步长选择。
正式求解的 `upper`、副属性预算和叶节点仍检查最低减伤，因此原型没有忽略最终可行性，结果也保持一致。
但梯度所优化的松弛问题更宽，允许参考点偏向最低TEN以下的属性分配。
这可能改变切线和分裂顺序，使该受约束问题上的剪枝变差；不能只凭代码把它认定为全部回退的原因。

## 单项消融

仅补入最低TEN：`lambda = max(0, minimumRawTEN - referenceTEN) * 0.00001`，
将 `lambda * (TEN - minimumRawTEN)` 加入线性上界，同时在线搜索的方向导数中加入相应惩罚。
这个线性项在可行域非负，未改变原目标或可行集。迭代次数、候选、Worker、搜索策略及其他约束不变。

原梯度回退此前还做过配对复测，结果为普通15.42秒、梯度52.07秒。
本次补约束版本只运行一次，不给出统计置信区间。
分支数减少约42.7%，耗时减少约40.3%，说明该缺口确实影响这个原型的搜索效率。
最优伤害均为7.946312273986066，装备/镶嵌/食物属性重建、GCD、减伤条件验证通过。
实验版12项原生测试通过，包括900组独立穷举对照。

补齐后仍慢于普通版本，不能称回退已经解决，也不能把剩余约16秒全部归为梯度函数开销或某个缓存问题。
梯度迭代成本、根节点切线选择不保证各子树更紧、参考点/乘子收敛质量，都需要分别计时或做进一步消融。
这里没有逐子树记录两种切线之差，也没有直接计时本例梯度函数，故不作更强的主因断言。

这是原型约束处理尚不完整及收益判断尚不足的问题，不是“最低减伤目标天然不能用梯度”的证明。
生产内核未修改，实验未启用或部署。
