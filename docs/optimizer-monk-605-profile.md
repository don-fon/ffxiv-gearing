# 武僧 605 高暴击：慢分片 CPU 采样

停止此前缺少阶段信息的长任务，保留 `/tmp/mnk605-complete-high.log`。停止时仅完成 8/1344 分片，不能认定最优。选取下一批中的实际任务 8：食物 49240、精确速度贡献 369、候选分片 0/4、全范围 CRT 669–2472、中点 1570.5、固定合法伤害下界 27.280971280704218。

使用相同 TypeScript 求解器及 WASM 内核，在 Node 24.19.0/V8 中执行这个单独任务。私有采样脚本通过 TypeScript 内存变换包装候选准备、镶嵌生成、支配筛选、分组收缩、速度规划、端点 DP、树构建及 WASM 调用；不修改产品源码。规划完成后开始 120 秒 CPU 采样，间隔 1000 微秒。外部 inspector 连接负责停止采样，即使求解器同步忙碌也能保存结果。

| 自身采样时间热点 | 占比 |
| --- | --- |
| addStats：合并并分配属性对象 | 38.05% |
| visitFinalSpeeds：递归枚举精确速度路径 | 21.73% |
| 垃圾回收 | 19.85% |

以上为自身采样时间，不能再与父函数包含子调用的时间相加。阶段日志同时观察到数百万次 WASM 查询，其中大量查询很短。原生 WASM 内核仅占采样的一小部分，当前热点主要在 JS 路径枚举、属性对象复制与临时对象回收。不能将长时间没有浏览器进度消息直接解释成候选生成或 WASM 内核卡住。

代码对应 `src/optimizer.ts` 的 `visitFinalSpeeds`：每条路径执行 `nodes.concat(tree)`、`addStats(maxima, tree.maxima)` 等分配，之后叶端再调用原生上界。大量路径先支付枚举和对象创建成本，才能由原生预算界快速排除。原生预算剪枝的局部收益与整轮仍很慢并不矛盾。

这次是单任务的 Node/V8 定位实验，不是 4 Worker 的 Chromium 完整耗时测量；不同运行时、包装计时和采样本身会影响比例。不能把这些百分比视作所有分片或浏览器总耗时的精确分解，也未证明本任务最优。

后续应针对这些热点验证：复用递归中的节点数组、减少属性对象复制，以及在更高层的速度前缀上应用有效预算界，避免先枚举再逐次调用 WASM 排除。每项应在同一固定任务上验证结果与耗时，再回到整轮运行。
