# 梯度上界扩大测试（2026-10-27）

接续[第一轮实验](optimizer-gradient-relaxation.md)，本轮预先选择 14 个新案例，
仅比较原版和 `RELAX_MODE=2`（只使用梯度上界）。不改变算法，也不按结果挑选启用的职业。
第一轮“仅初始解”没有减少分支，故本轮不再重复该变体。

## 场景与口径

覆盖武僧、战士、画家、龙骑、武士、吟游诗人、白魔、骑士；同步品级涵盖
375、525、605、665、795。包括宽候选范围、窄范围、不同 GCD、高／低暴击、
最低坚韧减伤和比例折算。诗人原计划用 530，但页面没有该同步选项，采集前改为 525。

六个新职业/等级输入从实际页面触发输入构建并截获 Worker 请求，未手工缩放装备属性。
其他案例来自已有真实输入，仅修改清单中列明的条件。
[场景清单](benchmarks/gradient-expanded-cases.json)包含原始输入路径、修改项和候选数。

每个案例两个版本分别新建 Chromium，以 4 Workers、`--engine auto` 运行完整生产 Worker 流程。
先冻结两个构建目录，再开始计时；运行中不编译、不跑其他性能测试。
按案例交替原版／实验版的执行顺序。首轮每次限时 120 秒。
超时只表示在时限内未完成，不能据此计算准确加速比例，也不证明当前最佳解已经最优。

每格首次跑一次。秒级案例的小差异不足以支持稳定收益结论。
本轮使用与第一轮相同的实验补丁，不包含“同时保留两个上界”等后续设想。

## 首轮结果

14 个新案例共 28 次运行：13 对完整结束，最优目标值均一致；1 对双方超时。
已完成的案例中，没有新的案例达到耗时减少 50% 的采用门槛。
下表负数表示更快，正数表示更慢。秒级案例的小差异不作稳定性结论。

| 新案例 | 原版（秒） | 梯度上界（秒） | 耗时变化 |
|---|---:|---:|---:|
| 武僧605 / GCD1.93 | 超时（120秒） | 超时（120秒） | 无法判断 |
| 武僧605 / GCD1.95 | 91.24 | 72.26 | -20.8% |
| 武僧375 / GCD2.50 | 0.86 | 0.82 | -3.8% |
| 画家375 / 高暴击 | 2.57 | 2.72 | +6.0% |
| 画家375 / 低暴击 | 10.08 | 12.90 | +28.0% |
| 战士375 / 350–795 | 29.72 | 27.46 | -7.6% |
| 战士375 / 最低减伤10% | 8.98 | 13.46 | +49.9% |
| 战士375 / 折算比例10% | 23.82 | 63.69 | +167.4% |
| 龙骑605 / 580–605 | 1.63 | 1.70 | +4.0% |
| 武士665 / 640–665 | 10.99 | 12.76 | +16.1% |
| 诗人525 / 500–525 | 1.79 | 1.99 | +11.2% |
| 白魔375 / 350–375 | 1.22 | 1.22 | +0.6% |
| 骑士605 / 580–605 | 3.56 | 4.94 | +38.8% |
| 画家795 / 770–795 | 2.85 | 2.94 | +3.0% |

武僧 605 的 GCD 从 1.94 换为 1.95 后，实测收益只有约 21%；换为 1.93 时两版都在 120 秒超时。
战士宽范围约快 8%，最低减伤和折算比例 10% 则退步。龙骑、诗人、白魔和满级画家的原版已是秒级，
没有显示出值得采用梯度上界的收益。不同职业和条件下均不能将原先单个案例的收益直接推广。

## 原场景对照复测

额外复测原来的武僧 605、不限暴击、GCD 1.94，时限单独设为 300 秒：
原版 **151.56 秒**，梯度上界 **47.23 秒**，
完整耗时减少 **68.8%**。两版伤害均为 `27.30352779435699`，GCD 和候选范围验证通过。
原版搜索 576,765,845 个分支，实验版 95,104,951 个分支。

这次复测没有第一轮基线与短暂编译重叠的问题，仍显示明显收益。
但该收益没有在本轮其他已完成的新案例达到同等程度，因此仍不采用或部署当前原型。
本轮合计 30 次运行：28 次完成、2 次超时；不存在用超时阶段最佳解冒充精确最优解的结论。



## 校验

仅双方都完成时比较最终目标值：普通模式比较实际伤害，折算模式比较 score。
逐个完成的结果独立核对 GCD、暴击阈值、最低减伤或折算公式，以及所选装备是否属于候选。
同时核对两版的暴击范围定义一致。超时案例不会标记为最优值校验通过。

[原始结果及分片诊断](benchmarks/gradient-expanded.json)包含状态、时间、结果属性、
输入哈希和两版 WASM 哈希。超时记录中汇总的分支数只覆盖已完成分片，不代表全部搜索量。

## 复现

`scripts/benchmark-optimizer.mjs` 新增 `--dist`，与 `--skip-build` 配合使用，
允许对两个固定构建目录做交替测试，而不在基准运行之间修改源代码或重新构建。

按清单的 `source` 读取输入，将 `overrides` 浅合并到输入，并设定 `criticalPreference` 为清单的 `critical`。
两个构建目录分别来自原版和第一轮补丁的 `RELAX_MODE=2`，构建方法见第一轮报告。

```sh
node scripts/benchmark-optimizer.mjs --skip-build --dist /tmp/baseline-dist \
  --chromium /usr/bin/chromium --engine auto --workers 4 --timeout 120000 \
  --critical none --input /tmp/case-input.json --output /tmp/baseline-result.json
node scripts/benchmark-optimizer.mjs --skip-build --dist /tmp/bound-dist \
  --chromium /usr/bin/chromium --engine auto --workers 4 --timeout 120000 \
  --critical none --input /tmp/case-input.json --output /tmp/bound-result.json
```

高／低暴击案例分别使用 `--critical high/low`。所有实验输入、清单和结果都保留在仓库，
生产求解器和页面部署不变。

## GCD 1.93 完整补跑（2026-10-28）

首轮双方在 120 秒超时后，使用相同冻结构建、输入和 4 Workers 补跑至全部分片完成。
一次原版运行在约 21 分钟时随执行环境中断，未产生最终结果；该次不计入比较。
下表只使用之后两个版本各自完整的连续运行，不传入已知最优解。

| 武僧605目标 GCD | 原版（秒） | 梯度上界（秒） | 耗时减少 |
|---|---:|---:|---:|
| 1.95 | 91.24 | 72.26 | 20.8% |
| 1.94（对照复测） | 151.56 | 47.23 | 68.8% |
| 1.93（完整补跑） | 1333.92 | 155.05 | 88.4% |

1.93 两版均完成 4/4 分片，最优伤害均为 `27.16929816050764`。
根据候选装备、魔晶石上限和食物重新累加属性，与结果一致；GCD、唯一装备和槽位检查通过。
原版共检查 4,312,895,020 个分支，梯度方案共检查 682,828,643 个分支。
最终属性为 STR 2602、CRT 669、DET 2387、DHT 1968、SKS 857、VIT 2937，食物为炖剑山芋。

在这三个武僧测试点中，技速要求提高时，梯度方案的相对耗时收益确实增大。
这只是同一职业、同步品级和候选集合下三个点的观察，不能推广为其他职业或范围的规律。
本轮补跑新增了一个超过 50% 门槛的慢场景；首轮其他已完成案例的回退仍存在，当前原型继续不作为通用优化启用。
