# 坚韧减伤折算

坦克可选择“坚韧减伤折算”，输入“每 X% 坚韧减伤视为 1% 增伤”。默认关闭，输入默认值0.5，允许0.01–100。与“最低坚韧减伤”互斥：开启时不提交最低减伤约束，关闭后恢复原输入。可同时使用目标GCD、暴击偏好和装备锁定等条件。

用户确认采用线性折算，而非严格按每次牺牲相对伤害百分比复利。

设 D 为实际期望伤害，M 为坚韧减伤比例（5%写作0.05），X 为输入框数字（0.5%写作0.5）：

`score = D × (1 + max(0, M) / X)`

例如X=0.5、M=5%，评分为D×1.10。D已经包含坚韧本身的真实增伤，额外乘数只表达防御偏好的排序权重，不改变实际伤害。数值越小，越看重减伤。

## 实现

- JS与WASM使用相同评分；旧模式保持纯伤害排序。
- 原生ABI7的context[19]存放评分系数，旧JS/新WASM不匹配时按既有路径回退。
- 预算上界保留最乐观的坚韧折算倍数；原生线性上界也加入相同倍数的对数，避免用纯伤害界错误剪掉高坚韧方案。
- 求解器内部的damage变量及globalMinimumDamage下界使用目标单位；公开结果damage始终为真实伤害，新模式额外返回score。
- 规划、跨食物比较、Worker合并、全局剪枝下界和浏览器基准均使用score；结果显示伤害、折算评分及坚韧减伤。

## 验证

独立穷举对比JS/WASM及公开规划分片：三种暴击偏好、三档兑换比例、镶嵌、食物、锁定、排除、跨Worker下界。验证评分最优，并确认一些用例确实选择了低于纯伤害最优值的方案。原生300组独立穷举增加坦克折算覆盖，包含原生预算/线性上界、食物和GCD约束。

77项算法测试、16项生产浏览器测试、lint、生产构建、WASM源码/产物一致性检查通过。生产浏览器验证互斥切换、非法比例、关闭弹窗保留输入、按评分合并低伤害高防御结果，以及真实Worker的WASM与JS回退。
