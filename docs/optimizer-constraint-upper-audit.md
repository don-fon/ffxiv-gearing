# 最低坚韧减伤剪枝上界审查（2026-10-28）

现有上界对联合约束的松弛过宽。此前索引和分裂顺序的优化没有充分解决这一层。
本轮审查普通WASM上界，实验后恢复源码及dist；没有采用新算法或部署。

## 当前上界实际做了什么

`optimizerSearch.c` 的 `upper`、`budget_bound`、`plane_bound` 共同工作：

1. 技速最小/最大值判断GCD区间是否还可能达到；坚韧最大值判断是否可能满足最低减伤。
2. 从“副属性＋技速”的总预算中减去必需技速；副属性预算分配保留最低原始坚韧值。
3. 对每个真实候选组求线性伤害支持函数，保留组内属性关联，再把各组最大值相加。
4. 将独立最大属性伤害、预算上界、线性上界取最小值。

因此不是完全没考虑坚韧。问题在于这些约束分别存在于不同的松弛中，最后取最小值，
并不等价于在同一批实际候选上同时满足全部约束后，再求伤害上界。
收缩后的一个候选组可能包含多个部位，不能将支持函数简单描述为“每件装备各取一个最大属性”。

## 两个预算层面的缺口

- **下界过低**：当前节点已有的最低暴击进入了暴击函数割线计算，但预算削减仍允许把暴击降到人物基础值。
  信念、直击、坚韧也没有完整使用当前节点必带属性作为预算下界。这允许在模型里挪走当前候选实际上无法挪走的属性点。
- **缺少联合不可行判定**：必需坚韧加上当前分支必带的暴击、信念、直击，可能已经超过扣除必需技速后的预算。
  原削减循环没有在预算仍有缺口时直接判定不可行。

例如某组只有两种增量：A为暴击100、坚韧300、技速0；B为暴击100、坚韧0、技速100。
要求坚韧至少300、技速至少100时，两项各自的最大值检查都通过，但没有可行选择。
该组“副属性＋技速”最大总量400，扣除必需技速100后剩300；当前组必带暴击100再加必需坚韧300，已经需要400。
如果仍允许把暴击挪到基础值，就遗漏了这个联合不可行性。

这是安全但过宽的松弛：需要搜索到更深处才能排除，不代表一定返回错误配装。

## 预算修补实验：不能凭理论更紧就采用

原型为节点缓存最低信念、最低直击，结合现有最低暴击、最低坚韧；预算削减使用这些下界，并检查最低必需总量是否超预算。
ABI12、每节点28个f64，原版ABI11、26个f64。14项原生测试通过，包括900组独立穷举对照。

第一轮原型也影响了有分支上限的预热，混入起点变化：战士2.48＋10%从原88.29秒变为120秒未完成；
骑士2.45＋15%从42.70秒降到19.25秒。这一轮不能用于独立归因完整搜索上界的效果。

随后固定原预热，只在完整搜索启用预算修补，重新构建并通过同一组14项测试：

| 场景 | 原完整耗时秒 | 修补后秒 | 最优值 |
|---|---:|---:|---|
| 战士375/GCD2.48/最低10% | 88.29 | 88.35 | 一致 |
| 骑士605/GCD2.45/最低15% | 42.70 | 21.27 | 一致 |

均4 Workers、真实冷启动浏览器完整流水线，串行，每格一次；原完整基线复用此前混合约束测试，没有同轮重新交替测量。
战士总访问分支由约2.33亿降到约2.20亿，但耗时无改善；骑士明显受益。
不能将“新增必要条件”或某个病例收益作为联合约束瓶颈已经解决的证据，原型暂不采用。
[原始实验及固定预热复测](benchmarks/constraint-upper-budget-audit.json)；[实验补丁](experiments/constraint-budget-floors.patch)。

## 用真实候选检查联合松弛的潜力

从两个实际慢分片采集完整搜索的候选向量、食物、参考点、原始技速区间和最低减伤：

- 战士375/GCD2.48/最低10%，食物49240：29433个向量，固定前缀＋6组收缩候选。
- 骑士605/GCD2.45/最低10%，食物49248：66024个向量，固定前缀＋6组收缩候选。

采样时固定单一食物，所得参考点及初始伤害门槛属于这个固定食物子问题，不能冒充原完整多食物任务的全部初始状态。
每个候选组内部仍只选一个组合。离线LP允许组内做分数混合，形成原整数问题的上界；
分别加入暴击区间、最低坚韧、技速区间，检查同时约束比各自松弛强多少。
采用原有伤害线性上界及食物处理，未把非线性伤害替换为一套新的装备权重。

选取代表性的两个原始暴击区间：

| 上界构造 | 战士CRT 1226–1290 | 骑士CRT 1220–1284 |
|---|---:|---:|
| 现有最终上界，含预算约束 | 7.99012025 | 21.55017834 |
| 线性支持＋暴击区间 | 7.99012028 | 21.44958555 |
| 再加最低坚韧 | 7.95748520 | 21.42410665 |
| 暴击区间＋技速区间 | 7.99012028 | 21.25857326 |
| 暴击、坚韧、技速同时约束 | **7.94811234** | **21.22425310** |

表中是伤害上界，不是找到的实际配装伤害；各行不是网页求解耗时。
战士中单独加入技速对该线性松弛几乎没用，但与坚韧一起使用时能继续收紧，这正是分别处理会遗漏的联合效果。
第一行还包含原预算上界，其余行是线性支持松弛，因此后者个别值会略高；保留原上界取最小值可避免削弱已有约束。

已取4个战士区间、6个骑士区间核对：Python重建的现有上界与原生WASM根上界最大误差约1.07e-14。
LP结果使用非负对偶价格，再对所有真实候选重新求支持函数，得到带数值裕量的上界证书，
没有直接将浮点LP原始目标值当作可剪枝证书。

这些结果证明该联合松弛可以更紧，但尚未测量其在整棵树上的收益，不能据上界差值承诺端到端加速。
离线HiGHS用于诊断；网页运行时还需要轻量的价格求解、支持函数缓存和完整性能验证。

## 从这个模型出发的实现方向

在一个暴击区间中，原线性模型有 `log D ≤ c + Σ w·x`。
对最低坚韧T、最低技速S使用非负价格λ、μ，可得合法上界：

`U(λ, μ) = c − λT − μS + Σ组 max实际候选 (w·x + λTEN + μSKS)`。

可行解上增加的 `λ(TEN−T)+μ(SKS−S)` 非负，所以这个式子仍是上界。
技速上限、暴击区间的上下限可同样进入模型。自动选择让上界更小的价格，就把“为了达标必须牺牲哪些伤害属性”直接算进同一个模型。
价格只在整组候选的根部求取，后代用各自候选节点重新评价同一价格的支持函数，可以缓存，不要求逐子树重新优化。

后续应保留现有上界并取最小值，固定有限预热作为独立控制项；
先用独立穷举验证不会错剪，再跑已记录的4组真实混合约束和2.50对照。
运行耗时、最优性、内存及每项改动的边际收益都要验证，不能只用根上界变紧作为采用指标。
这条联合价格方案本轮尚未加入正式求解器。
