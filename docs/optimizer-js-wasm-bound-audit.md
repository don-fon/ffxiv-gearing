# JS／WASM 上界覆盖审计

2026-10-30。结论：**已确认主要是剪枝能力不齐，而非两套不同的约束定义。已补齐 JS 的最低坚韧预算预留，并共用公式适用性判断；较大的原生线性上界能力差异暂保留。** 审计阶段完成源码核对与隔离正确性实验；随后按用户“好改的先改”要求，已补齐 JS 最低 TEN 预留，并让 JS 与 WASM 适配器共用 `getSecondaryBudgetContext`。C 内核和 ABI 未改，没有把上界收紧比例当作性能改善。

后续决定：按用户要求，网页只使用 WASM 搜索，加载失败显示提示并允许重试，不再提供纯 JS 回退。下表保留为参考实现能力审计，不再要求为网页回退补齐全部 C 优化。JS 参考求解器用于测试／离线对照；正常 WASM 路线仍使用的 JS 外层预算界继续维护。

## 当前差异

| 机制 | JS | WASM／C | 判断 |
| --- | --- | --- | --- |
| 属性独立最大值的乐观评分 | 有 | 有 | 都使用真实取整、食物和目标评分；是较便宜的第一层界 |
| 高暴击下限、低暴击上限、最低减伤可行性 | 有；分布在 `feasibleDamageBound`、树查询和叶子检查 | 有；在 `upper` 与叶子检查 | 检查位置不同，不等于漏掉用户条件 |
| 副属性总预算 | 有 | 有 | 共同的四属性预算与对数切线模型 |
| 预算公式适用条件 | 使用共享判断 | 使用同一共享判断 | 已合并到 `getSecondaryBudgetContext`，避免漂移 |
| 最低减伤必须消耗的 TEN 预算 | **已补齐**，反解最低减伤所需原始 TEN | 已有同样的保守反解 | 本次已统一行为，C 侧计算及 ABI 保持原状 |
| 实际候选组的相关线性支持值 | 无这层原生算法 | 有；逐暴击段、按节点缓存两种支持值 | 更大的算法能力差异，不是一个遗漏的 `if` |
| 坚韧折算奖励与伤害联合取切线 | 没有原生相关切线；目标奖励包含在独立乐观评分中 | 有；将奖励的对数切线加到 TEN 权重 | JS 通常更松，没有把奖励从评分目标中删掉 |
| 整段 GCD 的速度预算预留 | JS 使用固定速度路径 DP，没有同样的整段后端 | 原生整段查询扣除最低速度消耗 | 搜索组织不同，不能直接把 C 代码复制到 JS 固定路径 |
| 武器／主属性与约束压力分裂排序 | 有基础树结构，JS 查询多按节点数量拆分 | 使用额外的主属性、TEN／CRT／速度压力信息 | 搜索顺序差异，不属于上界公式正确性 |

预算适用性两边都要求：坦克或可证明没有 TEN 的普通职业、基础属性不低于公式基准、装备副属性非负、没有固定数值的副属性食物。无 TEN 的判定都检查固定属性、食物、魔晶石维度、锁定镶嵌和候选装备；BLU 仍不进入普通无 TEN 模型。原生相关线性界另有正参考因子、食物等保护，因为它是额外一层算法；不能为追求形式一致删除这些保护。

上述审计针对当前正常输入模型。它不声称任意构造的负属性、负食物比例或非有限数都已获得统一的正确性保证。

## JS 上界也会影响正常 WASM 模式

固定速度路线在调用原生内核前，仍由 JS 的 `visitFinalSpeeds` 检查速度路径、计算独立界和副属性预算界。能够在这里提前排除路径，就能省掉后续原生查询。因此，JS 最低 TEN 预留的潜在价值不局限于“WASM 加载失败后的回退”。

同时，整段 GCD 路线提前进入原生查询，不经过这段属性状态 DP／固定速度外层预算界。因此不能保证补齐 JS 后所有默认 WASM 大案例都会加速。JS 回退缺少哪些能力，与哪些输入实际经过该能力，需要分别判断。

## 最低坚韧缺口的含义

原预算界从各属性独立最大值出发，按切线权重从便宜的属性上扣除多算的副属性预算。修改前 JS 允许把 TEN 一直扣到基础值；如果用户要求最低 10% 减伤，这种乐观分配可能已经不满足最低 TEN，但仍用于计算上界。

这会**放宽**候选域，通常使上界偏大、剪枝变弱。它没有让最终结果免于最低减伤检查，也不能据此判断现有 JS 会返回非法装备。

C 已将 TEN 可扣减下限提高到满足减伤所必需的原始值。它反解包含食物封顶的连续上包络，并预留取整／浮点误差，避免把可行点错误排除。移植时应复用这套保守边界，不能简单按整数比例换算而忽略食物与游戏取整。

## 隔离验证

在冻结副本中增加只读的原生根上界导出；关闭相关线性界，保留原生预算界。另以内存模块变换给 JS 加入与 C 相同的 TEN 下限计算，当时生产代码没有应用该变换；下列数据保留为原型审计记录。本次已将等价逻辑落实到源码。

对 1,800 个小型组合树独立枚举全部组合，核对最优值，并直接比较：原 JS 预算界、JS 预留 TEN 的实验版、C 预算界。涵盖坦克／无 TEN、四种主属性、物理／魔法武器、不同等级、食物封顶、分数属性和高／低／不限暴击。

| 指标 | 结果 |
| --- | ---: |
| 总案例 | 1,800 |
| 坦克／无 TEN 案例 | 1,200／600 |
| 预算公式可用 | 1,542 |
| 最低减伤大于零 | 800 |
| 最低减伤大于零且预算公式可用 | 685 |
| JS 实验版上界比原版更紧 | 296 |
| 原 JS、实验 JS、C 上界低估可行最优值 | 0 |
| 实验 JS 与 C 上界的最大绝对差 | 约 4.26×10⁻¹⁴ |
| 收紧案例中的上界降幅中位数／最大值 | 约 0.34%／3.60% |

原生搜索结果也逐例与穷举最优比较通过。无 TEN 的 600 例没有因该原型改变上界，符合预期。固定数值副属性食物等不满足预算条件的案例保留原有保守路径，不把它们算成收紧收益。

**这些数字描述上界，不描述耗时。** 小幅收紧可能排除大子树，也可能没有排除任何额外分支。没有端到端计时证据前，不认定有某个百分比的性能提升。测试能够排查实现错误，不替代浮点代码的形式化证明。

## 本次落实与剩余项

1. **已补齐 JS 最低 TEN 预留。** 每个固定食物的预算界只初始化一次反解，在节点查询时复用；同时覆盖 JS 参考求解和正常 WASM 模式的 JS 外层固定速度剪枝。
2. **已共享预算资格和基础下界构造。** `getSecondaryBudgetContext` 返回副属性维度、基础下界、无 TEN 标志及预算可用标志，两处都调用它。每次返回独立数组，JS 调整 TEN 下限不会污染其他查询或 C 上下文。C 仍自行计算其保守 TEN 反解，本次不改 ABI。
3. **暂不向 JS 参考求解器移植相关线性界、奖励联合切线和整段 GCD 路线。** 本次没有移植这些更大能力，也没有改食物候选、BLU 排除或规模阈值。

回归：将既有 2,000 组预算上界测试加入最低减伤要求与分数属性，验证不低估可行最优值、不比无约束界更松，并断言确有案例收紧；新增共享策略测试覆盖 BLU、基础值不足、负属性、TEN 装备／镶嵌／食物、固定数值食物及查询间数组隔离。全部 8 个 optimizer 测试文件通过；lint 与生产构建通过。

WASM 适配器新增对已有 optimizer 导出的依赖，相关测试与基准脚本的模块加载已同步。归档 HiGHS 脚本仅调整模块引用路径，没有恢复依赖或启用实验算法。

本次是小范围的一致性补齐，没有重新跑端到端性能矩阵，不声明具体提速。
